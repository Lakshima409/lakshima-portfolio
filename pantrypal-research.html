Research Project · Final-Year Project

PantryPal Intelligent Recipe Recommendation System

How machine learning and personalised food recommendations can simplify meal planning, support healthier eating, and reduce household food waste.

Research overview

Individual final-year research + build investigating limits in recipe/meal-planning platforms (Yummly, Eat This Much, Whisk) and proposing one integrated system: pantry + nutrition + recommendations + shopping lists.

Areas: ML, recommendation systems, personalised nutrition, food sustainability. Method: literature review, system analysis, iterative build, testing + evaluation.

View build case study<> Code

At a glance

  • Hybrid TF-IDF + cosine similarity + collaborative filtering (Python Flask service)
  • React + Node/Express + MySQL full-stack system
  • Two Flask microservices (:5001 recommender, :5002 diet planner) behind Node/Express; React never calls Flask/MySQL directly
  • Local heuristic fallback keeps endpoints live if an AI service is offline
  • UAT + feedback (reported): 83% accuracy, 0.7s API, 90–95% objectives
  • 249 server unit tests, PyTest for AI services, 40-assertion journey-check.js, GitHub Actions CI

01 · Research & problem discovery

Problem, gaps & research question

Problem statement

People have ingredients at home yet still struggle to decide what to cook within diet, nutrition and budget. Existing apps split recipe discovery, diet management, pantry tracking and grocery planning adding effort, extra purchases and food waste.

Literature review & gap

Reviewed intelligent food recommenders, personalised nutrition, pantry-aware suggestions, auto shopping lists, and ML/NLP recipe techniques; compared Yummly, Eat This Much, Whisk. Gaps: fragmented workflows, weak contextual personalisation, poor pantry utilisation, no combined decision support.

Research question

How can ML + automated pantry management deliver personalised recipes, maximise pantry use, and support healthier eating?

Aim & objectives

  • Survey existing systems; pick ML techniques for personalised recipes
  • Use pantry + diet signals in ranking; build weekly plans + missing-item lists
  • Evaluate via unit, integration, UAT and feedback
02 · Methodology & solution

How the research became a system

Methodology

Literature review + requirements + architecture/UML + Agile/Scrum build (React, Node/Express, MySQL, Python Flask recommender) + multi-stage testing.

Proposed solution

One workflow: personalised recipes, pantry management, dietary/nutritional filters, weekly plans, auto shopping lists, saved recipes.

ML approach

  • Content-based: TF-IDF recipe/ingredient vectors + cosine similarity ranking
  • Hybrid scoring with tunable weights: pantry match, dietary hard-filter, nutrition proximity, preference affinity, collaborative filtering, cold-start fallback
  • Collaborative: ratings + saved-recipe patterns for personalisation
  • Flask service behind Node API; time/season context signals

Technical honesty

Results below are the project evaluation scope positive relevance/usability signals, not proof of waste or health outcomes.

03 · Evaluation & reflection

Testing, findings & next steps

Evaluation

Unit + integration + UAT + feedback on usability and relevance. Reported: 83% recommendation accuracy, 0.7s API response, ~90–95% objectives met, 85%+ satisfaction. Backed by 249 server unit tests, PyTest for both AI services, and a 40-assertion end-to-end journey harness, with GitHub Actions CI running Node + Python + MySQL integration tests.

Limitations → future work

Prototype scope; needs larger/diverse cohorts, bigger benchmarks, image-based pantry, deeper nutrition personalisation, longitudinal waste studies.
