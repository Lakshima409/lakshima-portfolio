Software Architecture & Design Principles

Overview

This project explores how core object-oriented design principles translate into a real software system — using a fictional supermarket chain, Sampath Food City, as the case study. The work spans two layers: the theoretical foundations of good software design (OOP, UML, SOLID, design patterns, clean code) and their practical application to a retail data system, from raw data collection through to visualization and quality assurance.

What I did

1. Object-Oriented Design Foundations

Modeled system entities using encapsulation, abstraction, inheritance, and polymorphism. Explored relationship types between classes — association, aggregation, and composition — and applied them to real class structures such as a university-department relationship and a house-room composition. Produced UML class and inheritance diagrams to document system architecture and class relationships before implementation.

2. Design Patterns

Implemented and documented examples across all three categories:

  • Creational: Factory Method, Abstract Factory, Singleton, Builder, Prototype
  • Structural: Adapter, Bridge, Composite, Decorator, Facade, Proxy
  • Behavioral: Command, Mediator, Observer, Strategy, State

Wrote Java code samples demonstrating each pattern's structure and use case, with a focus on what problem each pattern solves.

3. SOLID Principles & Clean Code

Applied all five SOLID principles (Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion) to Java examples and refactored problem code into compliant versions. Documented clean coding practices including naming conventions, modularization, formatting, and maintainable folder structures.

4. Data Pipeline Design

Designed a full data pipeline for the Sampath Food City case study:

  • Data Integration: Consolidating data from manual systems and POS terminals into one analysis-ready dataset
  • Data Preprocessing: Cleaning, transforming, and validating data for accuracy and consistency
  • Data Analysis: Applying descriptive statistics, correlation, regression, clustering and sentiment-style analysis to sales, pricing, and customer preference data
  • Data Visualization: Selecting and justifying chart types for dashboards and reporting requirements

5. Automated Testing Strategy

Evaluated automation tools such as Selenium, Appium, Cypress, Katalon, Postman, and JMeter against language support, CI/CD integration, and cost. Designed a testing approach spanning unit, integration, smoke, performance, and regression testing. Wrote practical PyTest examples covering setup, parameterized inputs, and exception handling.

Why it matters

This project ties together software architecture theory and a practical, end-to-end data system — showing not just that I can write pattern-compliant code, but that I can reason about why a given principle, pattern, or tool fits a business problem from initial design through testing and deployment readiness.
